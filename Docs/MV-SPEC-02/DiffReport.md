#### 맵 구성 메모 (지금 코드가 하는 일)

- **플레이 구간 오브젝트**(탑·게이트·공방·계단·더미·원석·하수인 무리)는 이미 **표로 배치**한다: `311_templateObject`(종류 id·x·z, 템플릿 8종) + `314_spawnGroup`(무리 오프셋) → `Assets/Game/Scripts/MV.Run/Gen/LevelGen.cs`가 행을 그대로 깐다. 좌표는 정본 `PLACE`(L738)를 옮긴 값이다.
- **코드가 만드는 부분**: 결계(골목) 블록 칸과 끝 보너스 줄은 `MV.Run/Gen/FieldGen.cs`·`RunLevelBuilder.cs`가 `313_fieldGen` 규칙 값과 해시로 **생성**한다(어느 칸이 고양이·마법석인지, 블록 HP 보간). 미리 짠 배치가 아니다.
- **프리팹 배치는 지금 없다.** 맵을 프리팹으로 짜려면 프리팹(또는 에디터 도구)에서 311 행을 뽑아 저장하는 방식이나, 프리팹 자체를 읽는 로더가 필요하다. 07 §7.6.6 「배치 편집 도구 `MV/Placement Editor`」(씬 뷰에서 끌어 311 행 저장)는 **명세만 있고 구현되지 않았다**.
- 결계 칸을 미리 짜는 자리는 이미 표에 있다: `303_areaFloor.cellMode` = `Hash`(지금 전부) / `Baked`(`soulCells`·`soulAmts`·`diaCells` 열 사용, 07 §7.4.3, D-61). 검증기(`MV.Data/Validation/MvTableValidator.Semantics.cs`)는 Baked를 검사하지만 **런 코드(`MV.Run/Gen/FieldGen.cs`)는 Baked를 읽지 않는다**. 미리 짠 결계를 쓰려면 이 분기부터 넣어야 한다.
- 반영 계약을 정할 때 「배치 = 표/프리팹이 정본, 코드는 읽기만」을 완료 기준에 넣는다.

**정리**: 1·2번은 번호·테마가 맞아 이름(과 2번 카드 2장 정도)만 바꾸면 된다. 3~12번은 번호도 테마도 어긋난다. 테마가 비슷한 행으로 옮겨도 사수자리냥·쌍둥이자리냥은 대응이 없고, 카드 7장은 어차피 새 스킬로 다시 짜야 한다. 그래서 권장은 **3~12번은 번호(id)를 유지한 채 새 기준 순서대로 이름·테마·카드를 새로 채우는 것**(A)이다. 지금 꺼진 행이라 기존 플레이·저장에 영향이 없다. 상세 스킬·해금 조건은 새 문서 03 탭(작성 예정)이 정할 자리라, 03 탭이 나오면 카드 70장을 그 기준으로 채운다.

남는 결정 2가지:
- 메뉴 노출: 새 기준은 10종(11·12번은 데이터만) + 1번만 오픈. 지금은 12칸 + 1·2번 켜짐(2번은 Area 4 해금, D-74).
- 2번 해금: 새 기준은 「잠금」만 있고 해금 방법이 없다. 지금 표는 Area 4 도달, 3~12번은 야옹신 방울 구매([창작]). 03 탭 전까지 지금 값을 둘지 정한다.
